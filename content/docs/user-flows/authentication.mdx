<Callout type="info" title="Invite-only">

- No sign-up page: an admin or captain creates the account from Roster.
- The member activates it via the reset email.
- Better Auth (`src/lib/auth.ts`), Drizzle adapter, email + password only.

</Callout>

## Provisioning and activation

<Mermaid
  chart={`
sequenceDiagram
    autonumber
    actor Admin as Admin / Captain
    actor Member
    participant App
    participant Resend

    Admin->>App: addUser (roster:create)
    App->>App: signUpEmail with temporary password, insert player/coach row
    App->>Resend: requestPasswordReset → "Create a new password"
    Resend-->>Member: Link with token, redirectTo /new-password
    Member->>App: /new-password?token=... submit password
    App-->>Member: resetPassword ok → router.push('/login')

`}
/>

- **Password rules** (live on `/new-password`): 8–128 chars, at least one
  letter, one number and one special character.
- `LoginSchema` only enforces the length.

## Request gating

<Mermaid
  chart={`
flowchart TD
    A[Page navigation] --> B{Cookie present and cache fresh?}
    B -- no --> L["/login"]
    B -- yes --> C{"can(role, resource, 'view')"}
    C -- no --> F["/forbidden"]
    C -- yes --> P[Render page]
    P --> D[Server action] --> E{withResource: canAll?}
    E -- no --> X[forbidden]
    E -- yes --> O{Ownership check?}
    O -- mismatch --> X
    O -- ok --> S[Action runs]
`}
/>

- **Proxy** (`src/proxy.ts`): cookie, cache freshness, `view` check; on
  navigations only. `next-action` requests skip it.
- **`withAuth` / `withResource`** (`src/actions/auth.ts`): inside every server
  action. No session → `/login`; no permission → `forbidden()`.
- **Client session**: `usePermissions` and `Authorized` hide controls. Never
  trusted.

Details and the matrix: [Roles & Permissions](/docs/access/roles-permissions).

## Forgot password

<Mermaid
  chart={`
flowchart LR
    A["/login"] -->|Forgot password?| B["/forgot-password"]
    B -->|authClient.requestPasswordReset| C[Email sent]
    C --> D["/new-password?token=..."]
    D -->|authClient.resetPassword| A
`}
/>

- One `sendResetPassword` handler serves activation and reset.
- Both emails share the subject "Create a new password".
- A logged-in user on any auth route is redirected to `/dashboard`.
