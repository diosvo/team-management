- A private, role-based hub for one basketball club, in one Next.js app.
- Covers roster, training, attendance, matches, testing, assets and analytics.
- These docs record **why each page exists** and **how it is built**.
- Use them to check a change against intent and against the code.

## How a spec is written

Every feature page follows the same sections so readers know where to look:

<TypeTable
  type={{
    Purpose: {
      type: 'prose',
      description: 'Why the page exists and who it serves.',
      required: true,
    },
    Access: {
      type: 'PermissionMatrix',
      description: 'Role × action permissions, generated from ROLE_CONFIG.',
      required: true,
    },
    Flows: {
      type: 'Steps',
      description: 'Entry points and the main interactions.',
      required: true,
    },
    Rules: {
      type: 'list',
      description: 'Invariants the server enforces.',
      required: true,
    },
    'Data / API': {
      type: 'AutoTypeTable · TypeTable',
      description:
        'Tables, query params and server actions, typed from the source.',
      required: true,
    },
  }}
/>

<Callout type="info" title="Source of truth">
  Generated tables read the TypeScript source at build time. The rest is
  hand-reviewed: log meaningful changes in the
  [changelog](/docs/project/changelog).
</Callout>
