## Purpose

- Companion to the [Dashboard](/docs/features/dashboard), which exports a PDF
  on demand.
- This page **schedules** that PDF and keeps the **history** of every run.
- A team can schedule two reports, each sent once its period has closed:

<TypeTable

      required: true,
    },

- Both go out around **08:00 ICT** (`SEND_HOUR_LOCAL` in `DEFAULT_TIMEZONE`,
  `Asia/Ho_Chi_Minh`).
- No time or day picker: the window implies the cadence.

## Access

<PermissionMatrix resource="reports" />

- SUPER_ADMIN and captains hold every action; COACH and PLAYER only view.
- GUEST has no `view`, so the proxy redirects `/reports` to `/forbidden`.

<Callout type="info" title="Not every endpoint checks the resource">

- **Cron routes:** `CRON_SECRET` Bearer token, not a user session.
- **`/api/reports/download`:** a session on the report's team (or
  SUPER_ADMIN).
- **Dashboard ad-hoc email actions:** plain `withAuth`.

</Callout>

## Flows

<Steps>
  <Step>
    ### Schedules

    - One row per report: recipient count, next run, last run, enable switch
      (`edit`).
    - A paused schedule shows `-` as its next run.
    - Row click opens `UpsertReportSchedule` (`edit`).
    - **New Schedule** (`create`) offers only unscheduled reports; disabled
      once both exist.
    - `delete` lets users select and remove rows.

  </Step>
  <Step>
    ### Recipients

    - Picked from `getReportRecipients` (every team member); emails stored.
    - At least one required (`Add at least one recipient.`).
    - Only selected recipients receive the report.

  </Step>
  <Step>
    ### Run now

    - Generates now under the user's session, `scheduled_for = now()`, so it
      never collides with the planned occurrence.
    - Disabled while the schedule is paused.
    - Recovery path after a failed scheduled run.
    - Failure shows a toast, not an email.

  </Step>
  <Step>
    ### History

    - Every report, newest first, 10 per page.
    - Columns: period, time duration, status, delivery status, trigger,
      generation time.
    - Status shows the attempt count when above 1, and the error on hover.
    - **Download** only for a `success` run whose PDF is still stored.

  </Step>
</Steps>

## Rules

- **Precomputed `next_run_at`.** `computeNextRun` sets it on save and
  re-enable: 1st of the next period, 08:00 ICT.
- **No backlog.** Re-enabling computes from now, so a paused schedule never
  catches up.
- **Cheap polling.** Cron reads only overdue rows (partial index on enabled
  rows).
- **One run per occurrence.** History row inserted first under unique
  `(schedule_id, scheduled_for)`; replayed ticks can't double-send.
- **Locked claims.** Claims use `FOR UPDATE SKIP LOCKED`.
- **Crashed runs don't wedge.** A run `pending` over 10 minutes is taken over
  atomically by the next tick, reusing any stored PDF.
- **In-process retries.** Up to 3 attempts, 5 s then 20 s apart; the PDF is
  kept, so an email failure doesn't re-render.
- **Final failure still advances `next_run_at`.** Recover with **Run now**.
- **Failure alert.** A failed scheduled run emails the team's coaches, super
  admins and captain.
- **Atomic success.** `completeReportRun` closes the run and advances the
  schedule in one transaction.
- **Window resolved in ICT.** `intervalRange` uses `scheduled_for` in
  `DEFAULT_TIMEZONE`; 08:00 on the 1st (previous day in UTC) gets the right
  month.
- **One team per service account.** Cron renders as `PW_USERNAME` /
  `PW_PASSWORD`.
- **Other teams fail.** "Report session does not belong to the schedule team",
  instead of rendering wrong data.
- **Stored PDFs expire** after `RETENTION_DAYS` (90), including PDFs of runs
  that failed after rendering.

## Data

<AutoTypeTable path="src/drizzle/schema/report.ts" name="ReportSchedule" />
<AutoTypeTable path="src/drizzle/schema/report.ts" name="ReportHistory" />

- `report_schedule` is unique on `(team_id, interval)`.
- `report_history.status`: `pending`, `success`, `failed`, `expired`.
- `report_history.trigger`: `manual` or `scheduled`.
- `delivery_status` comes from the Resend webhook.
- Stored files: `analytics-<interval>-<digits of period>.pdf`.

## Acceptance

<Accordions>
  <Accordion title="A replayed tick does not double-send">

    - Two cron calls for one due occurrence: one history row, one email.
    - The second call reports `skipped_duplicate`.

  </Accordion>
  <Accordion title="Only unscheduled reports can be added">

    - Monthly exists: the editor offers only yearly.
    - Both exist: New Schedule is disabled.

  </Accordion>
  <Accordion title="Readers cannot change schedules">

    - COACH or PLAYER sees both tables.
    - No New Schedule or Run now; switch disabled; rows don't open the editor.

  </Accordion>
  <Accordion title="Expired reports cannot be downloaded">
    Once marked expired: Download is disabled and the URL returns 404.
  </Accordion>
</Accordions>
