## Purpose

- Registers the competitions the club enters and each one's player roster.
- Matches and achievements reference a league.
- The roster decides who counts as a participant.

## Access

<PermissionMatrix resource="leagues" />

- COACH views; SUPER_ADMIN holds every action.
- PLAYER, GUEST and captains have no `view`; redirected to `/forbidden`.

## Flows

<Steps>
  <Step>
    ### Browse

    - Columns: name, player count, dates, status badge; end date descending.
    - Search by name (`q`), filter by status.
    - Ended league with an achievement: icon to
      `/achievements?record=<league_id>` (needs `achievements:create`).

  </Step>
  <Step>
    ### Add or update

    - **+ Add** and row click open the same dialog.
    - Fields: name, start and end date, description, player picker.
    - League and roster are saved in one `upsertLeague` call.
    - `ongoing` / `ended` leagues are read-only: disabled fields, no picker,
      players cannot be removed, no Save.

  </Step>
  <Step>
    ### Delete

    - Only `upcoming` rows are selectable (`isSelectable`).
    - `removeLeague` runs per id; a summary toast reports the outcome.

  </Step>
</Steps>

## Rules

- **Status is derived, not stored.** No status column; `getLeagues` and
  `getLeagueById` use `deriveDateStatus`:
  - `upcoming` while `start_date` is in the future.
  - `ended` once `end_date` is past; otherwise `ongoing`.
- **Read-only after kick-off, on both sides.**
  - Client: the dialog and row selection disable ongoing and ended leagues.
  - Server: `upsertLeague` (update) and `removeLeague` re-derive the status,
    else “Only upcoming leagues can be changed”.
- **Validation** (`UpsertLeagueSchema`): name 3–64 characters, unique (DB);
  `end_date` after `start_date`; description ≤ 128 characters.
- **Roster sync** in `upsertLeague`:
  - Enters the caller's team in `league_team` (`onConflictDoNothing`); roster
    rows have a composite FK to that pair.
  - Diffs submitted `player_ids` against the stored roster.
  - Drops ids not on the caller's team via `getTeamPlayerIds` (`player`
    inherits its team from `user`).
  - Runs adds and removes with `Promise.allSettled`; one line per failure.
- **Partial roster failure is not rolled back.**
  - The league row and successful roster changes stand.
  - The response lists failed players; `/leagues` is not revalidated.
- **Deleting cascades** to `league_team`, `league_team_roster` and the
  league's matches.

## Acceptance

<Accordions>
  <Accordion title="Status follows the dates">
    Future start shows `upcoming`, then `ongoing` between the dates, then
    `ended`, with no write.
  </Accordion>
  <Accordion title="An ongoing league is read-only">
    Readonly badge, disabled fields, no Save; clicking a selected player keeps
    them in the roster.
  </Accordion>
  <Accordion title="Roster errors are reported per player">
    Other changes apply; the error toast names the player that failed.
  </Accordion>
</Accordions>
