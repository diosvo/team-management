## Purpose

- The shared list of venues.
- Training sessions and matches store a `location_id`: define once, pick
  everywhere.

## Access

<PermissionMatrix resource="locations" />

- COACH views; SUPER_ADMIN holds every action.
- PLAYER, GUEST and captains have no `view`; redirected to `/forbidden`.
- A coach can open the row dialog, but `upsertLocation` needs `create` and
  `edit`, so the server answers `forbidden()`.

## Flows

<Steps>
  <Step>
    ### Browse

    - Columns: name, address, last update; sorted by name.
    - `q` searches name and address.
    - The name links to a Google Maps search for the venue.

  </Step>
  <Step>
    ### Add or update

    - **+ Add** and row click open the same dialog; name and address required.
    - **Add** resets the form and stays open; **Update** closes it.
    - Saving revalidates `/locations` and mutates the `locations` SWR key
      (read by the session and match forms).

  </Step>
  <Step>
    ### Delete

    - Select rows and delete.
    - `removeLocation` runs per id; a summary toast reports the successes.

  </Step>
</Steps>

## Rules

- **Validation** (`UpsertLocationSchema`): name 3–128, address 3–256
  characters; both `NOT NULL`.
- **Global, not team-scoped.** `location` has no `team_id`; all teams share it.
- **Deleting a venue keeps its events.** `training_session.location_id` and
  `match.location_id` are `onDelete: 'set null'`.
- **Delete errors are flattened** to “Failed to delete location”; the DB
  message is hidden.

## Acceptance

<Accordions>
  <Accordion title="A coach sees the list without controls">
    A COACH sees every venue; no **+ Add**, no checkboxes.
  </Accordion>
  <Accordion title="A new venue is selectable elsewhere">
    A new location appears in the Training and Matches dialogs without reload.
  </Accordion>
  <Accordion title="Address is required">
    An empty address is blocked by validation.
  </Accordion>
