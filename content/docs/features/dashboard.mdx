## Purpose

- Post-login redirect (`DEFAULT_LOGIN_REDIRECT`).
- One-screen team health for every role: upcoming sessions and games, this
  year's win rate.
- Four attendance/match analytics for a date range (`?from=&to=`).
- The PDF report captures this same grid; no separate print route.

## Access

<PermissionMatrix resource="dashboard" />

- Every role can view.
- Export and email do **not** check the `reports` resource:
  - `POST /api/reports/dashboard` only needs a session (`verifySession`).
  - `getReportRecipients` / `sendReportEmail` are plain `withAuth` actions.
- So anyone who sees the dashboard can export or email it.

## Flows

<Steps>
  <Step>
    ### Filter

    - `DateRangePicker` (label "Time", earliest day `ESTABLISHED_DATE`).
    - Writes `from` / `to` as ISO days via `useDashboardFilters`; resets `page`
      to 1; `shallow: false` re-renders the Server Component.
    - Presets: this/last week, month, year.
    - No params: `loadDashboardFilters` falls back to `thisYear()`.

  </Step>
  <Step>
    ### Download

    - **Actions → Download** posts `{ from, to, filename }` to
      `POST /api/reports/dashboard`.
    - Saves `sgr-report-<period>.pdf`: `formatDateRange` digits joined by
      dashes (e.g. `sgr-report-01-01-2026-31-12-2026.pdf`).
    - Errors show a toast; nothing is stored.

  </Step>
  <Step>
    ### Send to...

    - `EmailReport` dialog: lazy, mounted only when opened.
    - Recipients come from `getReportRecipients`.
    - Posts `{ from, to, filename }` to the same route; base64-encodes the PDF.
    - `sendReportEmail` sends it as a Resend attachment with the
      `AnalyticsReport` HTML body.

  </Step>
</Steps>

## Rules

- **One Suspense boundary per card.** Each card is its own async Server
  Component (`_components/AnalyticsSections.tsx`); a slow query delays only it.
- **Shared reads once per request.** `fetchGameMatches` / `getUpcomingMatches`
  use React `cache()` keyed on primitives (`team_id`, plus `from`, `to` for
  `fetchGameMatches`).
- **Shared query by default.** On this-year range, the win-rate tile and
  matches chart share one query.
- **Completed matches only.** The win-rate tile and matches chart read 5x5
  matches through `getMatches`, so scheduled and cancelled matches carry no
  result and are not counted.
- **Client-only charts.** Each Recharts chart is `next/dynamic` with
  `ssr: false` (`LazyCharts.tsx`).
- **Lazy dialogs.** The two Quick Actions dialogs (mutually exclusive roles)
  also load lazily.
- **Empty means empty.** No data renders `EmptyState`; the attendance trend
  omits its average line instead of `0.0%`.

## PDF report

<Mermaid
  chart={`
flowchart LR
    A["Download / Send to..."] --> B["POST /api/reports/dashboard<br/>{ from, to, filename }"]
    B --> C["verifySession"]
    C --> D["Chromium via puppeteer-core<br/>cookies forwarded, 1200px viewport"]
    D --> E["goto dashboardPath(range)<br/>/dashboard?from=…&to=…<br/>wait #reports-dashboard, skeletons clear"]
    E --> F["Replace body with title + meta + grid<br/>force 2 columns"]
    F --> G["page.pdf → stream as attachment"]
`}
/>

- **Browser.** `getBrowser()`: system Chrome in dev; `@sparticuz/chromium-min`
  in production, binary from `CHROMIUM_PACK_URL`.
- **Lifetime.** Route `maxDuration` is 30 s; browser closed in `finally`.
- **Waits.** `#reports-dashboard` must appear within 3 s.
- **Skeletons.** Waiting for `.chakra-skeleton` to clear is best effort (5 s,
  timeout swallowed); empty dashboards show empty states, not skeletons.
- **Page.** 210 mm wide, as tall as the body, `printBackground`.
- **Response.** `application/pdf` with
  `Content-Disposition: attachment; filename=...`.

<Callout type="info" title="The range travels with the request">

- Opens `dashboardPath(range)` (`/dashboard?from=…&to=…`,
  `src/lib/report.ts`), so charts match the picker.
- `Duration:` is derived on the server via `formatDateRange`, never from the
  client.

</Callout>

## Acceptance

<Accordions>
  <Accordion title="Cards stream independently">
    With one slow query, other cards render behind their own skeletons.
  </Accordion>
  <Accordion title="The range lives in the URL">

    - Picking a range updates `?from=&to=` and re-renders the grid.
    - Reloading or sharing the URL keeps the range.
    - A PDF exported from it covers the same days.

  </Accordion>
  <Accordion title="Download yields a finished PDF">

    - PDF titled Analytics Overview Report, charts rendered, no skeletons.
    - A failing route shows a toast and saves nothing.
    - Generate and Email stays disabled until a recipient is picked.

  </Accordion>
</Accordions>
