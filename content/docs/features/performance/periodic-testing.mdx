## Purpose

- Records each player's score on the club's own tests (sprint, jump, …) by date.
- Main page: one testing day as a player × test-type matrix.
- Sub-routes: enter a whole session at once; maintain the test-type catalogue.

## Access

<PermissionMatrix resource="periodic-testing" />

- PLAYER only views.
- COACH, SUPER_ADMIN and captains hold every action: **Add Result**, **Manage
  Types**, inline cell edits, row selection on test types.
- Cell editability uses `can('periodic-testing', 'edit')`, as the server does.

## Flows

<Tabs items={['Matrix', 'Add result', 'Test types']}>
  <Tab value="Matrix">

    - Rows are players; columns are test types with a result that day, headed
      `Name (unit)`.
    - The date select lists `getTestDates()`; no date gives an empty matrix.
    - Only a date change reloads the server (`shallow: false`); it resets
      `type` and `page`.
    - `q`, `type` and `page` are client-only. 10 players per page.
    - Each cell is a Chakra `Editable` number input:
      - Empty cell → `createTestResult` with one row.
      - Filled cell → `updateTestResultById`; cleared → `deleteTestResultById`.
      - Unchanged value or clearing an empty cell writes nothing.
      - A failed write reverts the draft.

  </Tab>
  <Tab value="Add result">

    - Guarded by `canCreateTestResult()` on the server; fails → `forbidden()`.
    - Step 1: active players, up to five test types, a date (default today).
    - Step 2: a players × types grid of number inputs.
    - Clicking a column header or player name drops it from the selection.
    - Blank cells submit as `0`.
    - On success, redirects to `/periodic-testing?date=<date>`.

  </Tab>
  <Tab value="Test types">

    - `/test-types` lists the team's types with search and a unit filter.
    - **+ Add** and row click open the same dialog: name + one unit.
    - Units: `meters`, `percent`, `points`, `reps`, `seconds`, `times`.
    - Form defaults to `seconds`; the column defaults to `times`.
    - Selected rows delete in bulk; a type that still has results is refused.

  </Tab>
</Tabs>

## Rules

- **One result per player, test type and date.** `createTestResult` upserts
  on that triple:
  - `getExistingTestResults` resolves the batch in one `IN`-filtered query.
  - Rows are re-checked against the submitted keys (the filters cross-product).
  - One insert for new cells, one update pass for existing ones.
  - Toast: `{N} created, {M} updated`.
- **Unique type names per team.** Unique index `team_test_type_name` on
  `(team_id, name)`; 3–64 characters.
- **A type in use cannot be deleted.** `test_result.type_id` is
  `onDelete: 'restrict'`; `removeTestType` maps
  `test_result_type_id_test_type_type_id_fk` to “Type is being in use.”
- **Revalidation.** Results → `/periodic-testing`; types →
  `/periodic-testing/test-types`.

## Acceptance

<Accordions>
  <Accordion title="A player sees the matrix without controls">
    A non-captain PLAYER sees the matrix, stats and date select only. No **Add
    Result** / **Manage Types**; cells do not open an input.
  </Accordion>
  <Accordion title="Re-submitting a session updates rather than duplicates">
    A second identical submit reports `0 created, N updated`; one value per
    cell.
  </Accordion>
  <Accordion title="A type with results cannot be deleted">
    Fails with “Type is being in use.”; the type stays listed.
  </Accordion>
</Accordions>
