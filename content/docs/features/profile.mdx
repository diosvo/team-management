## Purpose

- Members review and edit their own details.
- SUPER_ADMIN manages any member's team data: role, position, state, jersey
  number.
- Reached from the account menu (own profile) or a
  [Roster](/docs/features/team-management/roster) row.

## Access

<PermissionMatrix resource="profile" />

- GUEST has no `view`: the proxy redirects to `/forbidden`, and
  `getUserProfile` calls `forbidden()`.
- Every other role holds `profile:edit`, so actions re-check ownership.

### `viewOnly`

UI-only flag from `getUserProfile`; disables Edit on the Personal and Team tabs.

- PLAYER / COACH: editable on their own profile, view only on another member.
- SUPER_ADMIN: view only on their own profile, editable on another member.

- `old_path` must be equal, not a prefix: Blob keys have a random suffix.
- `users/1` would prefix-match `users/12-abc`.
- So only the caller's current avatar is deletable.

## Flows

<Tabs items={['Overview', 'Personal', 'Team']}>
  <Tab value="Overview">

    - Avatar (initials fallback), name and role.
    - Upload overlay for the owner only (`sessionUser.id === user.id`).
    - `ImageUploader`: PNG or JPEG, up to 100 KB.
    - On success the session is refetched, so the header avatar updates.

  </Tab>
  <Tab value="Personal">

    - Email (read-only), full name, DOB, phone, citizen ID.
    - Save only when dirty and valid; Cancel resets.

  </Tab>
  <Tab value="Team">

    - Role, position, state, jersey number, join date (of the open
      membership stint).
    - Role and position: SUPER_ADMIN only. Jersey number: players only.
    - Saving with state `active` mutates SWR `CACHE_KEY.PLAYERS`, refreshing
      player pickers.

  </Tab>
</Tabs>

## Rules

- **Unique jersey per team.** `isJerseyNumberTaken` (excluding the edited
  member) runs before any write.
- **Private avatar Blobs.** Under `users/<user_id>` with a random suffix.
- **Avatar reads.** `getAvatar` returns a base64 data URL, cached by
  `useUserAvatar` (SWR immutable).
- **Join date lives on the membership.** `join_date` is read from and written
  to the member's open `user_team` stint, not a column on `user`.
- **Role switching.** `updateTeamInfo` upserts the `player` / `coach` row for
  the _submitted_ role and deletes the previous role's row.
  - User, stint and role rows are written in one transaction
    (`updateUserTeamInfo`).
- **Revalidation.** Every write calls `revalidatePath('/profile/<id>')`.

## Acceptance

<Accordions>
  <Accordion title="Ownership is enforced without the UI">

    - A PLAYER calling updatePersonalInfo or updateTeamInfo for another
      user_id is rejected.
    - So is their own user_id with a changed role. Nothing is written.

  </Accordion>
  <Accordion title="Admin edits others, not self">

    - Another member: Role, Position, State and Jersey Number are editable.
    - Own profile: both tabs view only; the avatar can still be replaced.

  </Accordion>
  <Accordion title="Avatar limits and replacement">

    - Over 100 KB or not PNG/JPEG: rejected client-side.
    - Valid upload: updates the avatar, deletes the old blob, refreshes the
      session.
    - old_path not equal to the stored image: rejected, nothing deleted.

  </Accordion>
</Accordions>
