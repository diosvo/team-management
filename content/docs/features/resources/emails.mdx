## Purpose

- Check what the portal has sent and whether it arrived.
- Preview the email templates without sending anything.
- Read-only: nothing on this page sends or changes data.

## Access

<PermissionMatrix resource="emails" />

- Only SUPER_ADMIN holds `emails:view`.
- Every other role, captains included, is redirected to `/forbidden`.

## Flows

<Steps>
  <Step>
    ### Browse sent emails

    - The page calls `resend.emails.list()` on the server.
    - The table shows **To**, **Subject**, **Status** and **Created At**.
    - Status is Resend's `last_event`, shown as a colored badge.
    - A Resend error replaces the table with the error message.

  </Step>
  <Step>
    ### Search and filter

    - Search matches recipients and subject.
    - **Status** filter: a checkbox group of the 12 Resend events.
    - Filtering and paging run client-side; state lives in the URL.

  </Step>
  <Step>
    ### Preview templates

    - Expand an item to see the rendered HTML with sample data.
    - **Reset password:** `ResetPassword` (`src/app/(auth)/_components`).
    - **Analytics Report:** `AnalyticsReport` (`reports/_components`).

  </Step>
</Steps>

## Rules

- **Not team-scoped.** The list comes from the Resend account behind
  `RESEND_API_KEY`, so it includes every team's emails.
- **One page from Resend.** No `limit` is passed, so only Resend's default
  page of recent emails is listed.
- **No local log.** Emails are not stored in the database; report runs keep
  their own delivery status in `report_history`.
- **Not every email has a preview.** The "Scheduled Report Failed" notice is
  inline HTML in `src/lib/report-schedule.ts`.
- **Subject prefix.** `sendEmail` prefixes every subject with `SGR - `.

Rows are Resend's `ListEmail` type; the page has no table of its own.
