## Purpose

- Inventory of what the club owns: balls, cones, jerseys, …
- Tracks quantity, condition and the player holding each item.
- Coaches consult it; admins maintain it from a single dialog.

## Access

<PermissionMatrix resource="assets" />

- COACH reads; SUPER_ADMIN holds every action.
- PLAYER, GUEST and captains have no `view`; the proxy redirects to `/forbidden`.
- A coach can open the row dialog, but `upsertAsset` needs `create` and
  `edit`, so the server answers `forbidden()`.

## Flows

<Steps>
  <Step>
    ### Read the metrics

    Three tiles from `getAssets().stats`:

    - **Total Quantity**: sum of `quantity`; click clears every param.
    - **Need Replacement**: `condition = poor`.
    - **Outdated**: `condition = obsolete`.
    - Clicking a condition tile sets the `condition` filter.

  </Step>
  <Step>
    ### Filter

    - Search by name; narrow by category and condition checkbox groups.
    - State lives in the URL: `q`, `category`, `condition`, `page`.
    - Filtering and paging run client-side over the team's full list.

  </Step>
  <Step>
    ### Add or update

    - **+ Add** and row click open the same dialog.
    - Fields: name, quantity, acquired date, owner (`assigned_to`, one player),
      category, condition, rich-text note.
    - **Add** keeps the dialog open and resets it for the next item.
    - **Update** closes it. A failed submit keeps the entered values.

  </Step>
  <Step>
    ### Delete

    - SUPER_ADMIN selects rows and deletes them.
    - `removeAsset` runs once per id; a summary toast reports the successes.

  </Step>
</Steps>

## Rules

- **Scoped to the caller's team.** `getAssets` filters on `team_id`;
  `upsertAsset` overwrites `team_id` with the caller's.
- **Unique names per team.** Unique index `team_asset_name` on
  `(team_id, name)`; two teams can each own a “Ball pump”.
- **Validation** (`UpsertAssetSchema`):
  - Name 3–64 characters; quantity 1–100 (default 1); note ≤ 128 characters.
  - Defaults: category `equipment`, condition `good`, acquired date today.
  - `obsolete` is hidden when adding; set it by editing.
- **Order.** Acquired date descending, then name. `NULL` sorts first on
  `DESC`, so undated assets lead.
- **Soft owner link.** `assigned_to` is `onDelete: 'set null'`; deleting a
  user keeps the asset. Deleting the team cascades.

## API

Server actions in `src/actions/asset.ts`, gated by `withResource('assets')`.

<TypeTable
  type={{

## Acceptance

<Accordions>
  <Accordion title="A coach sees the list without controls">
    A COACH sees the metrics and list; no **+ Add**, no selection checkboxes.
  </Accordion>
  <Accordion title="Filters are reflected in the URL">
    “net” + Equipment + Good gives `?q=net&category=equipment&condition=good`.
  </Accordion>
  <Accordion title="A duplicate name on the same team is rejected">
    A second “Ball pump” fails with an error toast; another team can add one.
  </Accordion>
</Accordions>
