## Purpose

- The practice schedule: when, where, how long, and how many turned up.
- Present rate per row comes from that session's attendance rows.
- This page is the summary;
  [Attendance](/docs/features/team-management/attendance) is the detail.

## Access

<PermissionMatrix resource="training" />

- GUEST has no access.
- COACH creates and edits; only SUPER_ADMIN deletes.
- Captains gain nothing: `CAPTAIN_PERMISSIONS` has no `training` entry.

## Flows

<Steps>
  <Step>
    ### Browse

    - Defaults to this month.
    - `interval` and `status` refetch on the server (`shallow: false`).
    - Location search `q` and paging filter in the client.
    - Stats:
      - **Completed Sessions**: click to filter by `completed`.
      - **Average Attendance**: records per session.
      - **Total Hours**: sum of `end_time - start_time`.

  </Step>
  <Step>
    ### Create / edit

    - **New Session** opens `UpsertSession`; clicking a row reopens it pre-filled.
    - Fields: date, start time, end time, location.
    - `UpsertSessionSchema`: defaults 20:00–22:00; refines `end_time > start_time`.
    - No status control: new sessions are `scheduled`, edits keep their status.

  </Step>
  <Step>
    ### Jump to attendance

    The date cell links to `/attendance?date=<date>`, that session's day view.

  </Step>
  <Step>
    ### Delete

    - SUPER_ADMIN selects rows and deletes in bulk.
    - The session's attendance rows cascade.

  </Step>
</Steps>

## Rules

- **A coach is required.** `upsertSession` calls `getTeamHeadCoach` on insert
  and update.
  - No COACH user: fails with "No coach assigned to the team".
  - Picks the first `role = coach` user; `coach.position` is not checked.
- **Present rate** = `(on_time + late) / attendances × 100`, one decimal; `0`
  with no records.
- **`(session_id, date)` is unique** (`training_session_id_date_unique`).
  - Target of `attendance`'s composite FK, so rescheduling moves attendance rows.
- **Nullable references.** Deleting a coach or location sets `NULL`; deleting
  the team cascades.
- **Period bounds** come from `TIME_DURATION[interval]`, evaluated once at
  module load.

- Server actions in `src/actions/training-session.ts`.
- Reads use `withAuth`; writes use `withResource('training')`.

## Acceptance

<Accordions>
  <Accordion title="Viewers see the schedule without controls">
    A PLAYER, captain or not, sees table and stats, but no **New Session** or
    selection checkboxes.
  </Accordion>
  <Accordion title="No coach, no session">
    With no COACH user, create or edit returns "No coach assigned to the team".
  </Accordion>
  <Accordion title="End time must follow start time">
    Ending at or before the start is rejected client-side: "End time must be
    after start time".
  </Accordion>
  <Accordion title="Date links to the day view">
    Clicking a date opens `/attendance?date=<date>`, not the edit dialog.
  </Accordion>
</Accordions>
