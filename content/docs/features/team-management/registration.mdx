## Purpose

- Produces the league organiser's document without retyping player data.
- Pick players and a league, optionally upload a fillable PDF, then export.
- Runs in the browser with `pdf-lib`; nothing is written to the database.

## Access

<PermissionMatrix resource="registration" />

- PLAYER, COACH and SUPER_ADMIN can open it; only SUPER_ADMIN and Captain use it.
- Every control is disabled when `!isCaptain && !isAdmin`.
- **UI-only gate.** No server action behind export; `getActivePlayers` and
  `getLeagues` are `withAuth` reads open to any signed-in member.
- **Sensitive data.** `getActivePlayers` returns full `User` rows (date of
  birth, phone, citizen ID); the only page where these reach the client.

## Flows

<Steps>
  <Step>
    ### Choose players

    - Multi-select over the team's `role = player`, `state = active` users.
    - Select-all and clear.

  </Step>
  <Step>
    ### Pick league

    - Single league picker fed by `getLeagues`.
    - The league name titles the PDF and slugs the file name.

  </Step>
  <Step>
    ### Attach PDF (optional)

    - One `application/pdf` file, up to 10 MB.
    - A help popover lists the field names below.
    - No template, or no fillable fields: the default roster is generated.

  </Step>
  <Step>
    ### Review & Export

    - Preview: paged table (no template) or filled PDF in an iframe.
    - Notes: up to 256 characters.
    - **CSV** and **PDF** download; **Save** stores the PDF for re-download.

  </Step>
</Steps>

## Rules

### AcroForm field mapping

- Only `PDFTextField`s are filled.
- Names are normalised: NFD, strip diacritics, `đ → d`, lowercase, drop
  non-alphanumerics.
- One regex per column, substring match: `Họ và tên`, `hoTen`, `full_name` →
  name.
- Player row = first digit group (`hoTen2` → second player); none → first.

- `FIELD_GUIDE` (`_components/main.tsx`) mirrors `FIELD_PATTERNS`
  (`_helpers/pdf.ts`); change both together.
- `updateFieldAppearances` re-renders fields with embedded GoogleSans, so
  Vietnamese glyphs display and the form stays interactive.

### Default roster

Generated when there is no usable template:

- A4, title, league name.
- Team block: coach line blank, captain from `player.is_captain`.
- Two-column player cards with a 3:4 photo placeholder.

A template whose fields match nothing still downloads, with a "No fields
matched" warning.

### Module split

<Tabs items={['roster.ts', 'pdf.ts']}>
  <Tab value="roster.ts">

    - Columns, `toRow`, CSV building (BOM, RFC 4180 quoting), download triggers.
    - No `pdf-lib`, so preview table, CSV export and saved list import it statically.

  </Tab>
  <Tab value="pdf.ts">

    - `buildRegistrationPdf` and all `pdf-lib` / `@pdf-lib/fontkit` code (~400 KB).
    - `await import()` at three sites: PDF export, PDF preview effect, save.
    - The bundler caches the chunk after the first call.

  </Tab>
</Tabs>

### Saved registrations

- `useSavedRegistrations` uses `localStorage` key `registration:saved`, per
  browser, best-effort.
- Each entry stores the PDF as base64 for re-download.
- Duplicate names get a ` (2)`, ` (3)` suffix.
- Notes live only in the saved entry, never in the PDF.
- File names: export `sgr-<league-slug>`, saved `saigon-rovers-<league-slug>`.

## Acceptance

<Accordions>
  <Accordion title="A COACH can look but not export">
    Player, league, upload and notes controls are disabled; preview stays empty.
  </Accordion>
  <Accordion title="Numbered fields fill per player">

    - `hoTen1`…`hoTen5` get the five selected players' names, in order.
    - `soAo3` gets the third player's jersey number.

  </Accordion>
  <Accordion title="A flat PDF falls back to the generated roster">
    A PDF with no form fields exports the default roster, not the upload.
  </Accordion>
  <Accordion title="CSV opens correctly in Excel">

    - Starts with a UTF-8 BOM and the Vietnamese headers from `COLUMNS`.
    - Values with commas, quotes or newlines are quoted.

  </Accordion>
</Accordions>
