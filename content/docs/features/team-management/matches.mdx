## Purpose

- One row per fixture: league or friendly, 5x5 or 3x3.
- Each match is `scheduled`, `completed` or `cancelled`; only a completed one
  has a score and a result.
- Season stats (win streak, win rate, points per game) are derived from the
  completed matches' scores, so the table never disagrees with itself.

## Access

<PermissionMatrix resource="matches" />

- GUEST can view, as on Roster.
- COACH and Captain create and edit; only SUPER_ADMIN deletes.

## Flows

<Steps>
  <Step>
    ### Browse

    - Defaults to this year (`from` / `to` filled per read).
    - **Time**, **Game Type**, **Match Type**, **Status** refetch on the server
      (`shallow: false`).
    - Opponent search `q` and paging filter in the client.
    - Stats: **Total Matches**, **Played**, **Win Streak**, **Avg Win Rate**,
      **Avg Points/Game**.
    - Score and result read `-` until a match is completed.

  </Step>
  <Step>
    ### Add / update

    - **Add** opens `UpsertMatch`; clicking a row reopens it pre-filled.
    - GUEST rows are not clickable (`onRowClick` is `undefined`).
    - Switches: **5x5**; **League Match** reveals the league picker.
    - Opponent: external teams only (`is_external`).
    - Date, time (default 19:30), location, status (default **Scheduled**).
    - **Our Score** / **Their Score** show only when status is **Completed**.
    - Moving off **Completed** resets both scores to 0.
    - No home-team field.

  </Step>
  <Step>
    ### Delete

    - SUPER_ADMIN selects rows and deletes in bulk.
    - `match_player_stats` rows cascade.
    - Deleting a team that played in any match is blocked (see Rules).

  </Step>
</Steps>

## Rules

- **Home is always us.** `upsertMatch` sets `home_team` to the caller's
  `team_id`; `getMatches` filters on it.
  - `diff_team` (`home_team != away_team`) rejects the club as its own opponent.
- **Status is stored, result is derived.** `status` is a `match_status` enum
  (`scheduled` | `completed` | `cancelled`), default `scheduled`.
  - `getMatches` maps `home_team_score - away_team_score` to `MatchResult`
    (`win`, `loss`, `draw`) for completed matches; others get `null`.
  - `unplayed_match_has_no_score`: a non-completed match must be 0–0, so a
    stored 0–0 is always a real draw.
  - `UpsertMatchSchema` mirrors that check as a field error.
- **Friendly means `league_id IS NULL`.** Turning **League Match** off nulls it.
- **League deletion cascades**, location deletion sets `NULL`.
- **Teams with matches can't be deleted.** `home_team` / `away_team` are
  `ON DELETE restrict`; `removeTeam` refuses with the blocking match count.
- **Scores are 0–100**, coerced to numbers by `UpsertMatchSchema`.
- **Played-only stats.** **Played**, win streak, win rate and points per game
  count completed matches only; **Total Matches** counts every filtered row.
- **Win streak** = longest run of consecutive wins among them.
- **Avg points per game** = mean of `home_team_score`.
- **`match_player_stats`** exists in the schema, but no UI writes it yet.
  - PK `(match_id, player_id)`: points, rebounds, assists, steals, blocks,
    turnovers, fouls, minutes.
  - `team_id` = the team the player played for at match time.

## Acceptance

<Accordions>
  <Accordion title="A GUEST sees results only">

    - List and stats render; no **Add**, checkboxes or row-click dialog.
    - Any save attempt is rejected by `withResource('matches')`.

  </Accordion>
  <Accordion title="Result follows the scores">
    A completed match saved 78–65 shows a `win` badge; 60–60 shows `draw`.
  </Accordion>
  <Accordion title="Unplayed matches stay out of the stats">
    A scheduled or cancelled match shows `-` for score and result and does not
    move the win rate.
  </Accordion>
  <Accordion title="A team with matches cannot be deleted">
    Deleting it in Settings → Teams is refused with the count of blocking
    matches.
  </Accordion>
  <Accordion title="A PLAYER cannot write">
    A non-captain PLAYER calling `upsertMatch` directly is rejected.
  </Accordion>
  <Accordion title="Own team as opponent is rejected">
    An `away_team` equal to the caller's team fails the `diff_team` check.
  </Accordion>
</Accordions>
