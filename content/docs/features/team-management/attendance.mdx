## Purpose

- Records who was on time, late or absent on a given date.
- Players file leave in advance; admins and coaches mark a whole session in one dialog.
- Rates feed the per-session present rate on
  [Training](/docs/features/team-management/training) and the Dashboard.

## Access

<PermissionMatrix resource="attendance" />

- PLAYER's `create` is leave for themselves only (see Rules).
- **Mark Attendance** and row checkboxes are gated on `can('attendance', 'edit')`.
- COACH and SUPER_ADMIN see them, matching the server. Captains gain nothing.

## Flows

<Steps>
  <Step>
    ### Pick a date

    - `date` defaults to today and is the only param the server reads.
    - `getAttendanceByDate` joins `user` for team scope; returns records + stats.
    - `q` (player name) and `status` filter in the client.
    - Clicking a stat tile sets the status filter.

  </Step>
  <Step>
    ### Submit leave (PLAYER)

    - **Submit Leave Request** captures a date and a reason (≤ 128 chars).
    - `UpsertAttendanceSchema` defaults `status` to `absent`.
    - `player_id` is the session user; the server checks it again.

  </Step>
  <Step>
    ### Mark attendance (SUPER_ADMIN, COACH)

    - **Mark Attendance** opens the bulk dialog: pick a date and players.
    - Tick **Absent**, or leave unticked for `late`; reasons are optional.
    - Submit calls `submitLeave` once per selected player.
    - No player selected: every active player is written as `on_time`.

  </Step>
  <Step>
    ### Update / delete

    - Select rows, then **On Time**, **Late** or **Absent** → `updateStatus`.
    - **Delete** → `removeAttendance`.
    - A summary toast reports the outcome.

  </Step>
</Steps>

## Rules

- **Ownership.** A PLAYER (captain included) with `values.player_id !== user.id`
  gets `forbidden()`. COACH and SUPER_ADMIN may file for anyone.
- **One record per player per session or per date.** Two partial unique indexes:
  - `unique_player_per_session` on `(player_id, session_id)`, session set.
  - `unique_player_per_date` on `(player_id, date)`, `session_id IS NULL`.
  - No UI sets `session_id` today, so the date index is the one that fires.
  - Either violation shows "`<id>`: Already submitted".
- **Date is bound to the session.** Composite FK `(session_id, date)` →
  `training_session` cascades; a `NULL` session skips the check.
- **No `team_id` column.** Scope comes from `player → user.team_id`.
- **Defaults differ by layer.** Column: `on_time`; leave form: `absent`.
- **Present rate** = `(on_time + late) / total × 100`, two decimals.

## Acceptance

<Accordions>
  <Accordion title="Leave creates an absent record">
    A PLAYER's leave creates one `absent` row for the date, with their reason
    and their own `player_id`.
  </Accordion>
  <Accordion title="Leave for someone else is forbidden">
    A PLAYER calling `submitLeave` with another `player_id` gets forbidden; no
    row is created.
  </Accordion>
  <Accordion title="Duplicates are rejected, per session or per date">

    - Second session-less record, same player and date: "Already submitted".
    - Same date with distinct `session_id` values: both accepted.

  </Accordion>
  <Accordion title="Bulk marking fills the day">
    Bulk submit with no player selected creates an `on_time` row for every
    active player on that date.
  </Accordion>
</Accordions>
