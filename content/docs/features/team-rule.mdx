## Purpose

- Single source of truth for the team's policies.
- Members read it; admins edit it in place, with no export or re-upload.
- Stored as HTML from the TipTap editor, on the team row itself.

## Access

<PermissionMatrix resource="team-rule" />

GUEST has no `view`, so the proxy redirects `/team-rule` to `/forbidden`.

<Callout type="info" title="One right for a singleton">

- The rule is two columns on the team row, which always exists.
- So `upsertRule` is a plain update needing only `team-rule:edit`.
- Requiring `create` too would lock captains out.

</Callout>

## Flows

<Steps>
  <Step>
    ### View

    - `getRule` reads `rule_content` and `rule_updated_at` from the team row.
    - No content yet: "Please wait for admin to set up the rule."
    - **Copy** copies HTML + plain text, with the last-updated line as footer.

  </Step>
  <Step>
    ### Edit

    - **Edit** / **Preview** toggle the same `RichTextEditor.Root` (no remount).
    - Unsaved changes show **Save changes?**, which calls `upsertRule(html)`.
    - The toast reads "Added rule successfully" the first time, "Updated rule
      successfully" after that.

  </Step>
</Steps>

## Rules

- **One rule per team.** Stored in `team.rule_content` (null until first
  save); there is no separate `rule` table, so it goes with the team.
- **Client-only editor.** `next/dynamic` with `ssr: false`; TipTap uses
  `immediatelyRender: false`.
- **Revalidation.** Save calls `revalidatePath('/team-rule')`.
- **Timestamp.** `rule_updated_at` shows as "Last updated on …".
  - Only `upsertRule` sets it, so renaming the team or changing its logo is
    not a rule revision.

## Acceptance

<Accordions>
  <Accordion title="Guests are redirected">
    A GUEST navigating to `/team-rule` lands on `/forbidden`.
  </Accordion>
  <Accordion title="Readers see no edit control">
    A PLAYER or COACH sees the content and the Copy button, but no Edit button.
  </Accordion>
  <Accordion title="Admin save is visible to all">
    After a SUPER_ADMIN saves, every permitted role sees the new content and
    timestamp on next load.
  </Accordion>
</Accordions>
